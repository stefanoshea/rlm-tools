---
name: rlm-explore
description: Explore large codebases inside a confined Python sandbox (`rlm-tools`) instead of dumping raw files into context. Use for broad cross-repo searches, counting or aggregating patterns across many files, multi-hop call tracing, or read-only inspection of untrusted repositories.
---

Use native read/grep tools for a single known file or narrow lookup. Open an `rlm-tools` session when raw search matches or multi-file reads would bloat context, or when inspecting an untrusted repository in an OS-confined read-only sandbox.

## Workflow

1. **Start one session** with `rlm_start(path, query, code=...)` using the absolute repository root. Keep `include_guidance=False` and `include_metadata=False` for compact startup, and optionally pass an initial `tree()` / `grep_summary()` script in `code=` to save a turn. Check `available_functions` in the response (external model helpers appear only when the root is enabled in `RLM_EXTERNAL_ROOTS`). For N-item recursion (`rlm_recurse_batched`), set `max_llm_calls ≈ 4×N` (default `300`; each child uses ~3–4 LLM calls). If `other_open_sessions` appears in the response, close stale sessions when done.
2. **Batch 3–5+ operations per `rlm_execute` call.** Orient with `tree()` or a wide case-insensitive `grep_summary()`, filter candidates in Python, and inspect surviving files with `outline(path)` (classes, methods, functions with `parent`/`depth` where `parent=None` and `depth=0` mark module-level defs, decorators, fields, line spans), `enclosing(path, line)`, `find_assignments(path, target)`, line-sliced `read_file(path, start_line=..., end_line=...)`, `read_files()`, or `grep_read()`. Print only distilled findings — or call `rlm_finalize(value)` for structured output. Variables and file reads persist across `rlm_execute` turns; if printed stdout is truncated, `_last_stdout` retains the full output for paging in follow-up calls.
3. **Route semantic vs. computable work:**
   - **Computable counts, lists, and line spans:** Compute directly in sandbox Python using `outline()`, `enclosing()`, and `find_assignments()` (do not delegate exact counts to sub-LLMs or hand-parse Python indentation).
   - **Many-item semantic judgement audits** (too much text for one context, each item needs reading & judgement): Use `rlm_recurse_batched()` (children can read code) when the child must check code; use `llm_query()` / `llm_query_batched()` only when the full context is already in the prompt. Give each child the file path and line span (from `outline()`), not pasted text, and instruct it to return structured `{item, claim, file_line, evidence}` JSON so the parent can verify cited lines in code. Watch for `[BUDGET_EXHAUSTED]` on child results (split large files/items if a child hits its tool-output budget). `rlm_recurse_batched()` keeps children read-only/sandboxed, works in clients without subagents, and avoids concurrent-subagent limits. (In Claude Code without `RLM_EXTERNAL_ROOTS`, delegate independent sub-questions in parallel to the bundled `rlm-explorer` subagent; note `RLM_SUB_PROVIDER=claude-cli` defaults `execution_timeout_seconds` to `180`.)
4. **Close the session** by passing `end_session=True` on your final `rlm_execute` call (or calling `rlm_end(session_id)`) once every required fact is verified from sandbox output.

## Boundaries & Gotchas

- **RE2 regex:** `grep`, `grep_summary`, and `grep_read` use linear-time RE2 (no lookarounds or backreferences). When a pattern needs Python `re` features, narrow candidates first and run `re` inside the worker on bounded `read_file()` slices.
- **Truncation:** Watch for `TRUNCATED` banners or `truncated: true` fields; narrow `path` or the pattern rather than treating truncated output as exhaustive. Explicit `grep(..., max_matches=N)` caps results at `N` without raising; workspace limits raise unless `allow_partial=True`.
- **Scan filtering vs. read-only isolation:** Directory scans, greps, and `glob_files(pattern)` honour `.gitignore` and skip binary files; pass `glob_files(pattern, include_ignored=True)` to list gitignored non-secret files, and direct `read_file`/`read_files`/`outline`/`enclosing`/`find_assignments` still work on known paths. Enforced read-only isolation blocks symlinks, hardlinks, `.git`, `.npmrc`, `.pypirc`, `.netrc`, `settings.local.json`, `.mcp.local.json`, and `.env*` secrets (except `.env.example`/`.sample`/`.template`) across all helpers. Switch to native edit tools once exploration is complete and edits are needed.
