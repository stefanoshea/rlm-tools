Explore the target repository using only the RLM sandbox tools (`rlm_start`, `rlm_execute`, `rlm_end`).

## Rules

1. **Open one session and start exploring immediately** with `rlm_start(path, query, code=...)` using the absolute repository path. Keep `include_guidance=false` and `include_metadata=false`, and pass an initial `tree()` or wide `grep_summary()` in `code=` to save a turn. Keep the default `max_llm_calls=300` on `rlm_start` (covers up to ~64 items at ~3–4 LLM calls per child); only pass a higher `max_llm_calls ≈ 4×N` when `4×N > 300`, and never lower it below `300` for audits. If `other_open_sessions` is returned, remember to close stale sessions.
2. **Route by task shape:**
   - **Exact counts, lists, fields, and line spans:** Compute directly in sandbox Python using `outline(path)` (for classes, methods, functions with `parent`/`depth` where `parent=None` and `depth=0` mark module-level defs, decorators, fields, and line spans), `enclosing(path, line)`, `find_assignments(path, target)`, and `read_file(path, start_line=..., end_line=...)` for targeted line slices instead of indentation heuristics.
   - **Many-item semantic judgement audits** (e.g. auditing 20+ tools, endpoints, or handlers against descriptions or specs): Do **not** try to read or grep-skim all items in parent Python (that drops subtle bugs). When `rlm_recurse_batched` is in `available_functions`, enumerate all items and line spans with `outline()` in Python and dispatch **one child per item** via `rlm_recurse_batched` (children can read code; use `llm_query` / `llm_query_batched` only when the full context is already in the prompt). Give each child the file path and line span (from `outline`), not pasted text, ask each child to return structured JSON `{item, claim, file_line, evidence}`, verify the cited lines in parent Python, and check for `[BUDGET_EXHAUSTED]` markers (split large files/items if a child hits its tool-output budget). Note `max_llm_calls ≈ 4×N` (default `300` covers up to ~64 items). `rlm_recurse_batched(prompts)` returns `list[str]` aligned with `prompts`. If a later print or parsing line raises an error after `rlm_recurse_batched` returns, any variable assigned before the error is already saved in session state — inspect that variable in the next call instead of re-calling `rlm_recurse_batched`.
3. **Batch 3–5+ operations per `rlm_execute` call.** Filter candidates in Python variables, inspect surviving files with `outline()`, line-sliced `read_file()`, `read_files()`, or `grep_read()`, and `print()` only concise distilled findings (or call `rlm_finalize(value)`). If printed stdout is truncated, page through `_last_stdout` in follow-up calls. Pass `glob_files(pattern, include_ignored=True)` if you need gitignored non-secret files.
4. **Respect sandbox boundaries.** Allowed imports only (`re`, `json`, `collections`, `math`, `fnmatch`, `itertools`, `functools`, `operator`, `string`, `textwrap`, `difflib`, `statistics`). Never import `os`, `glob`, `pathlib`, or `ast`, and never call `open()`, `exec()`, `eval()`, `getattr()`, `type()`, `dir()`, or `str.format()`, and never access `__dunder__` attributes (like `.__name__`) — use `isinstance()`, f-strings, and built-in helpers instead.
5. **Watch for `TRUNCATED` banners.** If `grep_summary`, `tree`, or `grep_read` reports truncation (or `grep`/`glob_files` raises a truncation error), narrow `path=` or the pattern rather than treating partial results as complete.
6. **Close cleanly** by passing `end_session=true` on your final `rlm_execute` call (or call `rlm_end(session_id)`).
7. **Return concise, grounded output.** Include exact file paths, symbol names, and line numbers observed in sandbox output. Never return raw file dumps.
8. **If RLM tools fail or are unavailable**, report the exact error cleanly without fabricating results.
